# Assistant instructions

Restrictions on how the assistant works in this repository. This file contains nothing else: no project facts, decisions or design. Those live in [dev/architecture/](./dev/architecture).

## Working rules

- The project is in the architecture phase. Do not write application code, install software or change the system unless explicitly asked. Answer design questions in the chat.
- Do not edit this file unless explicitly asked.
- Put all architecture in `dev/architecture/`, one file per concern, and add new files to its `README.md` index. Do not repeat architecture elsewhere.
- Read the relevant file in `dev/architecture/` before working on that area.
- Never move, modify or delete files on the user's real drives unless explicitly asked. Tests use temporary directories only.
- Do not use Python for the application. Do not extend `dev/architecture/samples/organiser.py`.

## Code conventions (when code is requested)

- `cargo fmt` and `cargo clippy -- -D warnings` must pass.
- Library code returns `Result` and uses `thiserror` for error types. No `unwrap()` or `expect()` outside tests.
- Tests live next to the code in `core` and use temporary directories.
- Prefer small, explicit types (`Move`, `FileEntry`, `Plan`) over loose maps.
- Comment only code that needs clarification.
